# Project SEKAI (JP): exact charts from the game's SUS files

Every Project SEKAI chart is a SUS text file ("generated by Ched", `#REQUEST "ticks_per_beat 480"`), the game's own
format. The files are exact: they give BPM changes, hi-speed changes, lanes, widths, slide paths with easing, and every
judged object. Everything below is on GitHub raw, so this source runs on the cloud machine and nothing waits on the PC.

Code: `src/vsrgconv/sources/sekai.py` (adapter) and `src/vsrgconv/formats/sus.py` (parser). Tests:
`tests/test_sekai.py` with `tests/fixtures/sekai_sample.sus` (every note type) and `tests/fixtures/sekai_master_sample.json`.

## Catalog fields

- `song_id` is the game's music id.
- `title` is the game title. `title_romaji` is the title itself when it has no kana or CJK; otherwise it is a Hepburn
  romanisation of `pronunciation`, made by `sekai.romanize`. Folders are named `<id>-<romaji slug>`.
- `artist` is the `creatorArtistId` artist from `musicArtists`, else the composer. `artist_romaji` is built the same
  way as `title_romaji`.
- `genre` is the unit display name, taken from `musicTags`:
  - exactly one unit tag gives that unit;
  - songs with several unit tags, or tagged `other`, go to `その他`;
  - songs tagged only `vocaloid` go to `VIRTUAL SINGER`.

  The tag mapping is `light_music_club` → Leo/need, `idol` → MORE MORE JUMP!, `street` → Vivid BAD SQUAD,
  `theme_park` → ワンダーランズ×ショウタイム, `school_refusal` → 25時、ナイトコードで。. All the tags are kept in
  `extra.tags`.
- `bpm` is `"150"`, or `"lo-hi (main)"` when the BPM varies.
- `date_added` is `publishedAt` as a JST date.
- `extra` holds:
  - `lyricist`, `composer`, `arranger`;
  - `published_at` and `released_at` in ms;
  - `vocals`: type, caption, singer names, asset;
  - `filler_sec`, `pronunciation`, and `categories`, `full_length`, `collaboration_id` where present;
  - `unreleased` when `publishedAt` is in the future.
- Each chart: `native` (`APPEND` ...), `level` (= `playLevel`), and `note_counts = {"combo": totalNoteCount}`.

## Format

The parser is `formats/sus.py`, and its module docstring is the reference. Semantics come from the open-source readers
of the official files: Next-SEKAI/sonolus-next-sekai-engine and its predecessor NonSpicyBurrito/sonolus-pjsekai-engine
(`sus/analyze.ts`, `sus/convert.ts`, `usc/convert.ts`), sevenc-nanashi/usctool, and Sekai-World/pjsekai-scores.

- **Time.** A data line spreads its 2-char pairs evenly over its measure: `beat = measure start + i/n × length`. The
  measure lengths come from `#mmm02`, which is 4 in every official file. The beat is an exact `Fraction`. The
  ticks-per-beat value is only used by `#TIL`, whose offsets are in ticks.
- **BPM.** `#BPMzz` defines a BPM and `#mmm08` changes to it. Ids are base 36 (`BPM6V` exists).
- **Hi-speed.** `#TIL00: "m't:speed, ..."` becomes `ScrollChange`s. The items are often out of order and are sorted.
  One-tick bursts of speed 10000 are the game's "teleport" effect and are kept as they are. `#HISPEED 00` selects the
  group; official files use only group 00. A second group in use would give a warning, and its notes keep
  `extra.hispeed`.
- **Offset.** `#WAVEOFFSET` gives `offset_ms = -WAVEOFFSET × 1000`. It is 0 except in one file (7.31). The game's own
  audio file has `fillerSec` seconds (usually 9) of silence before beat 0. That value is in `meta.source.filler_sec`
  for whoever attaches audio. It is not added to the offset, because the audio is not ours yet.
- **Lanes.** SUS lane x (base-36 header char) maps to IR lane x − 2. The width is the second char of the pair.
  - Lane 0 tap type 4 is a skill marker.
  - Lane 15 tap type 1 is FEVER CHANCE and type 2 is SUPER FEVER.

  These markers go to `meta.source.sus_events`; they are not notes.

| SUS | IR |
|---|---|
| `#mmm1x` type 1 / 2 | `tap` / `ex_tap` (`extra.critical`) |
| type 5 / 6 (trace) | `tap` / `ex_tap` with `extra.trace` |
| type 4 (damage) | `mine`. None occurs on playable lanes in the JP data. |
| `#mmm5x` type 1 / 3 / 4 on a tap | `flick`, `extra.direction` = up / up-left / up-right (critical and trace flags as above) |
| `#mmm3xy` slide stream y: 1 start, 3 relay, 5 invisible relay, 2 end | `slide`, or `hold` when no point moves. `path` holds the points after the start; `PathPoint.easing` is the curve of the segment arriving at that point. `extra.points` names each point: tick, trace, hidden or end. |
| tap 2/6/8 at a slide's start | `extra.critical` |
| tap 5/6 at a start / end / relay | `extra.start` / `extra.end` = trace, or point `trace` |
| tap 7/8 at a start / end | `extra.start` / `extra.end` = `hidden` (no judgement; 8 also critical) |
| tap 3 at a relay | a tick attached to the curve. It is not a shape point; its beat offset goes in `extra.attach`. Tap 3 at an invisible relay deletes that relay. |
| `#mmm5x` 2 / 5 / 6 at a slide point | easing `in` / `out` / `out` of the next segment |
| `#mmm5x` 1/3/4 at a slide end | `extra.end_direction` |
| `#mmm9xy` guide | `other` with `extra.guide`, `extra.color` (yellow if tap 8 at its start), `extra.fade` (`none` if tap 7/8 at its end) |
| `#mmm2xy` hold | `hold` (`extra.sus_hold`). The only ones in the data are 20 lines on side lanes (429 easy/normal, 431 hard, 138 append). Those are kept verbatim. |

Anything else is kept verbatim in `meta.source.sus_unrepresented` and named in the warnings, as c2s.py does. The
header (`#TITLE`, `#REQUEST`, ...) is in `meta.source.sus`.

### Conflicts and duplicates (these appear as warnings on the chart)

- **Slides sharing a channel.** Two slides in one channel can meet at the same beat, one ending as the next starts. At
  equal times the parser orders relays first, then the end, then the start, so the order of lines in the file does not
  matter. Next-SEKAI goes by line order.
- **Stacked taps.** Several tap-channel objects can share a lane and time. They become one note: critical or trace if
  any of them is, with the first one's width.
  - `stacked taps identical` (416 charts) are exact duplicates.
  - `stacked taps merged` (69 charts) differ in type or width.

  Counting them once is what makes the combos match.
- **Duplicate slides.** Two slides can start at the same lane and time (`duplicate slides`, 16 charts). The later one
  wins, as in Next-SEKAI.
- **Modifiers without a target.** Some tap 3/7/8 objects sit on nothing (`modifier without target`, 27 charts). They
  are ignored.

## Combo

The game's combo (`formats.sus.sekai_combo`, stored in `meta.source.combo` with its parts) has these parts:

- every tap, critical, flick and trace counts 1;
- each slide start counts 1, and each slide end counts 1, unless hidden (tap 7/8);
- each visible relay (tick or trace) and each attached tick counts 1;
- each slide adds one hidden tick on every half beat strictly between its start and its end, on the chart's absolute
  half-beat grid (`half_beat_ticks`). Next-SEKAI adds the same hidden ticks (`TransientHiddenTickNote`).

This rule gives the published `totalNoteCount` for all 3,765 first-source charts and all 2,657 fallback charts. One
extra rule was needed:

- **A hidden end with a flick still counts.** 690 惑星ループ APPEND has the only slide end in the data with tap
  type 8 *and* a flick. Next-SEKAI drops that flick and gets 1170 against the published 1171. The parser keeps
  `end_direction` on a hidden end and counts it. This rests on that one case.

Guides, mines, skill and fever markers do not count.
